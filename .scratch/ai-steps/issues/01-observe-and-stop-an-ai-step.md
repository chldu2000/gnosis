# 01 开始 AI 步骤并让模型停手

**What to build:** 发起执行的人选定模型后，可通过现有执行入口运行一个 AI 步骤。模型收到目标、控件树和截图，并可在第一次观察后直接停手。该步骤返回已执行，提供结束截图，后续断言可以继续。

**Blocked by:** None (can start immediately)

**Status:** resolved

见[第三阶段规格](../spec.md)。复用已载入用例和设备接口，从执行环境取得模型地址、模型名和密钥。接入 Go 进程内的 OpenAI 兼容多模态接口。模型访问只发生在真正执行到 AI 步骤时。首先支持不带动作的停手决定。

读取界面失败时不发模型请求。模型设置缺失、请求失败、时限用尽或停手决定带有额外动作时，步骤和用例结果都是错误。错误中只放可公开的诊断。测试用本地模型服务、设备替身和可控时钟，通过执行入口验收。

- [x] 执行到 AI 步骤时，本地模型服务收到已载入目标、当轮控件树和实际截图，并使用执行环境选定的模型
- [x] 首轮停手时，AI 步骤为已执行，轨迹为空，没有设备动作，并携带结束截图
- [x] 模型停手后，随后的一条预期断言能够执行
- [x] 普通用例、拒绝开始的执行、被前置断言阻塞的执行均无需访问模型
- [x] 缺少模型设置、请求失败或超时、控件树或截图读取失败均得到错误，后续步骤不执行
- [x] 密钥、完整请求、原始响应及认证头不出现在执行记录和可见错误中

## Comments
