# 在工作台从设备界面选取元素

## Problem Statement

编写者需要猜测定位器，也很难在设备已跳转或断开后判断 AI 坐标点击当时指向哪个元素。

## Solution

Windows 工作台提供同一个选择器来查看 Android 设备当前界面和 AI 坐标点击前保存的界面。编写者在截图与控件树中选取元素，用候选定位器创建或修订步骤。

## User Stories

1. 作为编写者，我想在新建用例中直接选元素，以便手工编写时无需配置模型。
2. 作为编写者，我想在设备上导航后手动刷新，以便决定采集哪个界面。
3. 作为编写者，我想知道设备是否被其他执行占用，以免干扰正在运行或暂停的执行。
4. 作为编写者，我想从截图选中元素时看到对应的树节点，也能从树定位截图区域，以便分辨父子元素。
5. 作为编写者，我想查看元素的边界和可用属性，以便在重叠区域选到需要的节点。
6. 作为编写者，我想看见候选定位器及本次采集的匹配数量，以便识别列表里重复的资源 ID。
7. 作为编写者，我想把选中的定位器填入已有步骤，或新增动作与断言，以便复用现有用例。
8. 作为编写者，我想自行填写预期值，以便开关当前为关闭时也能编写要求开启的断言。
9. 作为编写者，我想点选截图时设备保持原状，以便编辑点击步骤时不会提前触发动作。
10. 作为草稿复核者，我想断开设备后仍能在动作前截图和树中选择元素，以便修订坐标点击。
11. 作为草稿复核者，我想查看动作后的界面，以便核对实际到达的详情。
12. 作为回归负责人，我想在目标换行后重跑，以便确认定位器仍能找到原商品。

## Implementation Decisions

- 采集通过本机执行进程，遵守设备占用。把同一次采集的截图、屏幕尺寸、元素边界及层级一起用于选取，刷新后用新材料计算高亮和匹配数。
- 候选定位器沿用现有条件、匹配规则及次序。选取只改变编辑状态，普通步骤与断言由现有表单编辑、校验和保存。
- 为需要复核的 AI 坐标点击在会话中关联对应轮次的动作前材料，动作后截图继续用于核对结果。截图作为文件附件保存。缺少动作前材料时明确说明不可离线选取。
- 手工选取可以独立交付；AI 离线复核复用同一选择器，并接入可编辑的用例草稿。

## Testing Decisions

- 以 Windows 工作台为验收入口，沿用工作台交互测试和可控设备。通过刷新、双向选择、编辑、保存、重载等可见行为验收；核对设备端收到的动作。
- 用 Android 开关验证点选不会切换状态；用重复 ID 和父子边界重叠的列表验证选择及匹配计数；竞争设备占用时原执行仍可继续。
- 真机上执行通过的 AI 商品列表用例，断开设备后替换坐标，调整列表顺序再连接，无模型重跑并由原断言核对详情。

## Out of Scope

首批设备为 Android，宿主编辑器为 Windows 工作台。实时投屏、操作录制以及历史报告导入另行安排。

## Further Notes

Windows 工作台已支持 Android 在线选取和断开设备客户端后的草稿复核，真机已验证开关状态保持、商品换行后独立重跑通过。操作入口见[工作台使用说明](../../docs/desktop-execution.md)。

手工选取只依赖现有手工编辑流程。离线复核的下游入口见 [AI 用例草稿](../ai-assisted-case-authoring/spec.md)。
