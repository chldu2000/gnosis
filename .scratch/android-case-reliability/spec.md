# Android 用例的编写、执行与失败诊断

Status: ready-for-agent

## Problem Statement

作者在一台设备上录入了「找到商品，提交搜索，检查购物车数量」，换一个字号或加载慢一点的界面，点击就可能过早发生。同名元素还会让一条断言因查到了另一行商品而通过。用例一旦失败，截图、步骤号和结果经常不足以区分目标没出现、目标不唯一、值错误和观测失败。维护套件的人还需要知道上个用例留下了什么状态，以及 CI 的绿色结果是否真的包含产品断言。

## Solution

让作者在现有 Windows MyGo 工作台编写定位、动作和断言，在同一次采集上预览匹配结果，由共享执行核心在设备当时的界面重新判定。右栏给出结论和下一步操作，离线报告保留可复核的证据。CI 与桌面共用判定。已经有的相对定位、草稿复核、报告跳转和设备占用继续作为这些问题单的起点。

**建议先交付 01 的购物车诊断场景**，并用 17 记录当前人工基线。随后用 02、03、04、05 跑通动态长列表；输入提交与应用起点可独立推进。测试数据先完成 12 的保护，再做 13 的绑定。14–16 的完成物首先是可复现证据；开源项目具备类似功能不足以证明当前平台、服务版本与设备组合可用。

## User Stories

1. 作为用例编写者，我希望看到断言最后读到的值，以便判断应用是否真的显示错误。
2. 作为排查者，我希望区分零命中、多命中和无法读取界面，以便选择修订定位器、报告缺陷或修复环境。
3. 作为编写者，我希望按稳定的部分显示文本或描述查找商品，以便数量和倒计时变化后仍能定位。
4. 作为编写者，我希望看到屏内范围和匹配数，以便识别预加载项与重复元素。
5. 作为编写者，我希望要求唯一目标、比较候选数量和识别缺失属性，以便避免偶然通过。
6. 作为编写者，我希望断言元素存在但文字不再含有错误提示，以便验证恢复后的状态。
7. 作为执行者，我希望给晚出现的点击目标设时限，以便慢设备也能完成步骤且提交只发生一次。
8. 作为编写者，我希望在指定列表内向下查找，以便同一用例适应不同字体和列表长度。
9. 作为编写者，我希望分别执行回车、输入法搜索和追加文本，以便覆盖用户真正使用的输入路径。
10. 作为执行者，我希望显式指定冷启动或深链，以便用例具有可说明的起点。
11. 作为套件维护者，我希望区分主流程和清理结果，以便判断下一条用例是否还能安全开始。
12. 作为套件维护者，我希望复用有来源的公共步骤，以便修改一处后也能定位每次引用的失败位置。
13. 作为执行者，我希望知道缺少哪项设备能力或资源，以便在开始之前修复环境。
14. 作为排查者，我希望报告保留执行时的应用版本和屏幕条件，以便对比两台设备的结果。
15. 作为 CI 维护者，我希望离线校验全部引用并可要求预期断言，以便区分仅完成动作与验证通过。
16. 作为 CI 维护者，我希望读取带次序的结构化结果，以便重复引用和未开始用例都能被准确归档。
17. 作为编写者，我希望换一组数据就能重跑同一用例，以便验证多个输入而无需复制步骤。
18. 作为执行者，我希望使用敏感输入时能预知记录和模型会收到什么，以便保护测试账号。
19. 作为 Android 用例编写者，我希望区分本次动作的提示与历史提示，以便准确判定短暂反馈。
20. 作为排查者，我希望区分受保护界面和设备采集故障，以便知道当前步骤是否仍有足够证据。
21. 作为产品维护者，我希望用有人工标签的对照样本评价视觉判断，以便知道哪些缺陷容易漏检。
22. 作为工作台维护者，我希望度量作者从失败到找到原因的时间，以便用真实操作决定下一轮优先级。

## Implementation Decisions

- 共享加载器、执行核心、结构化执行记录是语义的归属。桌面原生表单、元素选择器、CLI、AI 动作解码与用例草稿复用这些规则。涉及新动作时，一并验证 AI 参数允许列表、轨迹、报告展示、草稿另存和无模型重跑；涉及新格式时，一并验证旧文件、未知字段与 YAML 保存往返。
- 普通精确定位、相对定位和旧断言的多候选行为继续兼容。计数使用可说明的范围；未建立参照范围不能得出零个。显示文本与屏幕文字保持不同来源。屏内几何范围无法判定是否被浮窗遮挡。严谨的预览可复用执行匹配逻辑，实时执行必须重新读取设备。
- 设备操作经现有平台协议适配；每个平台分别记录「已验证／不支持／未验证」。文件可离线编写，选定设备后再展示能力差异。扩展输入或启动不会在执行前隐式清理应用，机密输入、受保护窗口和纯视觉判断的边界由专单验收。
- 工作台分三个位置承接改动。步骤详情配置预期和时限，元素选择器预览同一采集的命中与范围，右栏负责执行环境、进度和可操作的失败原因。保存草稿、预览和校验不得把编辑行为变成真实设备动作。完整报告仍由系统浏览器打开。
- 闭集动作、断言属性、清理段和截图例外均是对当前产品行为的**拟议扩展**。实现相应问题单时同步维护设计、用例格式、CLI 与桌面说明。保护例外需对齐 ADR-0003/0005 的像素来源、ADR-0004 的输入法恢复及 ADR-0006/0007 的执行所有权；已有云端租约终止后不能因清理再安排动作。

## Testing Decisions

以下验收入口已经与维护者确认。测试从作者可观察的行为出发，以输入文件、设备实际收到的操作、执行结果和报告为判据。

- **主入口用 CLI／共享执行。** 用真实用例或套件文件通过现有加载与执行入口，在现有设备替身和可控时钟上安排不同时间的界面，读取最终报告。沿用既有断言、套件、取消、报告与 CLI 测试的做法。同一购物车断言分别遇到零命中、命中但值为 2、多候选；核对原因、动作次数和退出码。
- **桌面交互用 MyGo 工作台。** 沿用现有工作台与元素选择器交互测试：通过可见控件修改、预览、保存、重新打开并执行，同一份文件再交 CLI 验证。覆盖紧凑与常规窗口、未保存草稿、同名用例、文件版本不符、断线重连；不为测试另建一个匹配器或桌面执行器。
- **平台承诺用设备证据。** 输入法动作、滚动容器、Toast、受保护界面和平台能力分别记录设备、应用版本、起点、动作和反例。人工可用性另记观察与耗时，自动化时间单独列出。可复用现有 Android 试点；无对应真机材料的另一平台继续标为未验证。

## Out of Scope

本轮范围限于声明式用例、现有 MyGo 桌面壳与本地执行进程。通用脚本循环、任意设备命令、跨步骤动态表达式、静默重试、单进程多设备调度和替换桌面框架均在范围之外。已有的容器与方向相对定位无需重新实现。受限正则、字号或遮挡的普适视觉判定，以及未通过验证的平台能力，保留给后续有样本支持的独立决策。

### 社区先例如何落到 Gnosis

- Playwright 在动作前等待适用条件，Trace Viewer 把动作和当时的观测关联起来。这里分别借鉴到 04 的「观察可重复，下发一次」和 01 的「最后一次观测随步骤保存」。Web 的事件接收、遮挡判断不能直接套用到设备控件树。[动作前检查](https://playwright.dev/docs/actionability) · [Trace Viewer](https://playwright.dev/docs/trace-viewer)
- Appium Inspector 可把树上选中的元素与截图、属性联动。Gnosis 已有这个入口，02 和 03 增加条件预览和候选数即可。Maestro 的滚动查找显式描述目标、方向与上限，05 将其用于长列表，并另外规定容器边界、唯一目标与停止原因。[Appium Inspector](https://appium.github.io/appium-inspector/2026.7/session-inspector/source/) · [Maestro](https://docs.maestro.dev/reference/commands-available/scrolluntilvisible.md)
- Robot Framework 将用例清理与可复用资源作为独立概念；08 和 09 采用声明式动作与静态展开。Playwright 的多种报告面向不同读者；11 从 Gnosis 已确定的执行记录生成机器摘要，同时保留离线 HTML。[Robot Framework 用户指南](https://robotframework.org/robotframework/latest/RobotFrameworkUserGuide.html) · [Playwright Reporters](https://playwright.dev/docs/test-reporters)
- uiautomator2 分开提供输入法动作和普通按键，并展示 Toast 缓存的读取与清除。06 与 14 需要在实际分发版本验证这两类行为。Android 的受保护窗口还可能产生空白截图；15 专门验证能否区分保护与普通黑色界面。[uiautomator2](https://github.com/openatx/uiautomator2) · [Android 受保护界面](https://developer.android.com/security/fraud-prevention/activities)
