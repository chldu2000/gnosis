# 03 按数量、唯一性和元素状态写断言

Status: ready-for-agent

Blocked by: [01](01-assertion-evidence.md)、[02](02-locator-matching.md)

[所属规格](../spec.md)

两个同名开关中只有另一个开启时，测试作者要能察觉目标不明确。

## 实现与边界

文本或属性断言可选「要求唯一」；省略沿用任一候选满足即成立。数量断言对同一控件树中符合条件的元素计数，可选等于、至少、至多；显式 index 与计数互斥。增加显示文本不包含、描述包含和屏内断言；否定文本要求目标存在。先实现 selected、focused；clickable、scrollable、password 各自声明平台可观测性，缺失属性依现行规则不成立，读树失败为错误。

## MyGo 桌面交互

「检查方式」切换后显示对应的比较符与期望字段；选择器并排展示实际值和可编辑的期望值。多候选时显示计数，允许返回选择器缩小范围。

## 验收条件

- [ ] 两个开关中一个满足时，旧断言通过；显式唯一断言轮询至时限后失败或阻塞。
- [ ] 覆盖零匹配的数量等于 0、零匹配的否定文本、属性缺失与 false、参照缺失时的数量等于 0；缺少参照不能证明数量为 0。
- [ ] 验证屏外和部分露出；元素详情中的未知属性标为未知，Android 真机验证选中标签和焦点切换。
