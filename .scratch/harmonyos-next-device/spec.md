# 用共享用例在 HarmonyOS NEXT 设备执行测试

## Problem Statement

已有用例通过 Android 设备执行。测试人员需要在 HarmonyOS NEXT 真机上运行相同格式的步骤，区分元素不匹配、设备能力不足及执行环境故障。

## Solution

将基于 hdc 协议和系统 uitest 的适配器接入现有设备选择和共享执行核心。用公开 CLI 完成首轮 NEXT 真机验收，再由现有工作台设备入口使用同一能力。

## User Stories

1. 作为测试人员，我想识别并明确选择在线 NEXT 设备，以便把用例发到正确设备。
2. 作为操作者，我想看到设备离线或被占用的原因，以便在执行前排查。
3. 作为编写者，我想通过应用标识和可选入口启动应用，以便从约定界面开始。
4. 作为编写者，我想按元素的文本、描述、类型或标识定位，以便沿用现有 YAML 结构。
5. 作为编写者，我想区分属性缺失和属性为假，以便正确判断前置断言和预期断言。
6. 作为编写者，我想在支持的设备上执行点击、长按、滑动、按键与文本替换，以便描述真实操作。
7. 作为测试人员，我想在报告中查看步骤截图并验证屏幕文字，以便判断真实界面的结果。
8. 作为套件操作者，我想多条用例共用所选设备直到套件结束，以便避免并发干扰。
9. 作为操作者，我想知道某项设备操作不受支持或通信错误，以便区分环境错误与预期断言失败。
10. 作为操作者，我想执行取消或中断后能再次使用设备，以便继续下一次验收。
11. 作为已有 Android 用例的维护者，我想复用套件顺序、报告和结果语义，以便评审两平台上的同一业务场景。

## Implementation Decisions

- 发布路径使用 Go 侧 hdc 协议，设备侧使用系统 uitest。按平台声明支持的操作；用例沿用既有设备操作与定位器。应用标识在 NEXT 对应 bundle，入口对应 Ability。
- 在已有设备选择和占用入口接入 NEXT。设备与平台绑定在执行时确定；跨平台场景可按被测应用实际标识或元素差异调整用例值。
- 设备负责将界面观察和动作映射至共享设备接口。定位、断言、离线 OCR、套件停止规则及报告继续由共享执行器处理。NEXT 的输入流程保持设备原有输入法。

## Testing Decisions

- 以同一公开 CLI 为主要验收入口，沿用已有 Android CLI 对在线设备、竞争占用、退出码、报告路径和附件的测试方式。协议替身模拟掉线及不支持操作，最终在 NEXT 真机核对已声明的能力。
- 在真机运行包含启动、元素动作、输入、断言和截图的用例，再用套件验证顺序、占用与收尾。另构造预期不成立和设备操作错误，核对两种结果以及报告。
- 共用控制树与像素文字的边界：前者检查元素属性，后者使用截图和离线 OCR。对照现有 Android 执行回归结果。

## Out of Scope

旧版 HarmonyOS、云端调度和针对 NEXT 的可视化选取元素属于其他范围。
