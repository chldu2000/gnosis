# 01 保存一份用例执行报告

**What to build:** 执行一条用例后，可取得静态 HTML 报告的路径。报告展示用例结果、步骤结论和结束截图，在浏览器离线打开。

**Blocked by:** None (can start immediately)

**Status:** resolved

见[第四阶段规格](../spec.md)。使用现有执行记录生成报告。显示用例名称、设备标识、开始时间、结果和可公开诊断。步骤按执行顺序显示，未命名的步骤用从 1 开始的序号。展示结束截图，缺图时明确标记。为每次执行生成独立位置，保存到用例目录树以外。

开始后发生的准备错误也应生成报告。拒绝开始不生成报告。报告保存失败保留原结果并返回保存错误。AI 轨迹的显示留给工单 02。

- [x] 通过用例执行入口取得报告路径，报告存在且所需图片可离线读取
- [x] 通过、失败、阻塞、错误和已执行均显示实际结果，未执行步骤不出现在报告
- [x] 有名称的步骤显示原名，未命名步骤显示序号，缺图有明确标记
- [x] 准备错误有报告，未开始的执行没有报告，断言轮询中间帧不进入报告
- [x] 同名和同一开始时间的执行不会覆盖，用例文件保持原样
- [x] 名称和诊断按普通文本呈现，保存失败不返回不可打开的路径且设备可再次取得

## Comments

通过 `Run` 验证离线 HTML、实际结果和结束截图，并覆盖拒绝开始、准备失败、保存失败及重复运行。见[报告测试](../../../report_test.go)。
