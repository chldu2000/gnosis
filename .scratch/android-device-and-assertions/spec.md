# 在一台 Android 设备上执行用例

## Problem Statement

测试编写者已经能把一条用例载入成有序的步骤，但这些步骤还不会在设备上发生。点击不会落下去，断言也不会被判定。一次执行没有结果，也没有每一步结束时的截图。命令行、桌面端和报告因此都还没有可执行的用例。

## Solution

提供一个**执行**入口。调用方给出一条已经载入的用例，以及一台选定的 Android 设备。入口按顺序做完动作和断言，并返回一份执行记录。

执行记录包含用例名称、设备、开始时间、结果、每一步的结论，以及每个作出结论的步骤结束时的截图。输入法若被这次执行切换过，在结果确定后切回；切不回去只记一笔注明。

设备不在线、设备已被占用，或这个进程里已经有一次执行，这次就不开始。没开始就没有执行记录。

失败、阻塞和错误立刻停下。用例的结果就是使它停下的那一个。没有预期断言的用例做完之后，结果是已执行。

## Implementation Decisions

- 对外增加一个执行入口。它接受一条已经载入的用例、一台设备和一个时钟。载入入口保持不变，执行不再解析文件，也不再补默认值。时长、时限和步数上限都用载入结果里的值。
- 入口的结果是两种之一：
  - 一份执行记录：用例名称、设备标识、开始时间、结果、按执行顺序排列的步骤结论，以及可选的输入法注明。每条步骤结论包含名称（可空）、结论、结束时的截图。
  - 一次没有开始的拒绝。拒绝没有执行记录。属于拒绝的情况只有：设备不在线、设备已被占用、这个进程里已经有一次执行尚未返回。
- 开始的顺序是：先判断能不能开始；能开始就记下开始时间并占住进程和设备；然后确保 uiautomator2 已安装；再按顺序执行步骤；结果确定后，若这次执行切换过输入法就切回；最后释放设备并返回记录。安装失败发生在已经开始之后，记录的结果是错误，步骤结论为空。
- 用例结果只按这些规则得出：
  - 动作做完，该步结论是已执行，继续。
  - 设备操作失败、界面或截图读不出来、屏幕文字识别不可用、比例越界、安装失败、执行途中设备断开，该步结论是错误，用例结果是错误，停止。
  - 遇到 AI 步骤，该步结论是错误，用例结果是错误，停止。不读取模型，不写轨迹。
  - 断言在时限内成立，该步结论是通过，继续。
  - 前置断言作出不成立的结论，该步是阻塞，用例结果是阻塞，停止。
  - 预期断言作出不成立的结论，该步是失败，用例结果是失败，停止。
  - 步骤都做完之后，若至少有一条预期断言且它们的结论都是通过，用例结果是通过；否则是已执行。
- 还没执行的步骤不出现在结论里。
- 断言轮询：第一次立即读取；不成立且时限还有剩余时，等待不超过 500 毫秒、也不超过剩余时限，然后再次读取。时限用尽仍不成立，才作出不成立的结论。时限为 0 时只读取一次。轮询的中间画面不写入记录。结束时的截图是作出结论那一次读到的画面。
- 动作不轮询。等待只推进时钟，不向设备发送手势，结束后截一张图。
- 定位器的资源 id、显示文本、描述、类型都按字面精确匹配，不裁剪空白。先用这些条件在控件树里过滤，树的顺序就是匹配顺序。第 n 个再从过滤结果里取，从 1 起。控件树节点包括当前不在屏幕内的元素。
- 控件树零匹配时，只有定位器的条件全都是显示文本、或显示文本再加第 n 个，才读取屏幕文字。屏幕文字的区域按先上后下、同一行再先左后右排列，第 n 个按这个顺序取。资源 id、描述或类型出现在定位器里时，树的零匹配就是没找到，不去识别屏幕文字。
- 控件树已有匹配时，不再看屏幕文字。
- 需要这次屏幕文字查找时，若截图失败或识别不可用，结论是错误。识别可用但没有对应文字，才是没找到。
- 动作要求恰好一个元素。零匹配，或多个匹配又没写第 n 个，都是错误，手势不发送。断言允许多个匹配：存在看有没有匹配；不存在看是不是一个都没有；文本等于、文本包含、属性等于看有没有一个匹配满足陈述。
- 点击和长按落在命中范围的中心。中心来自控件树节点的范围，或屏幕文字区域的范围。像素坐标四舍五入到整数。
- 比例使用闭区间 0 到 1。比例 0 对应像素 0，比例 1 对应该边长度减 1，中间按线性比例四舍五入。任一比例在区间外，该步是错误，对应的点击或滑动不发送。屏幕宽高读不出来时同样是错误，手势不发送。
- 输入文本只替换当前焦点中的全部内容，执行入口在输入前不额外点击。
- 启动应用的入口为空时，使用应用自己的入口。
- 每个作出结论的步骤都附带结束截图。截图这一步失败时，该步结论是错误；若此时用例还没停下，就按错误停下。
- 输入法切回发生在结果已经确定、设备尚未释放之前。只有这次执行确实切换过输入法才切回。切回失败时，结果保持原值，记录里加上注明。
- 设备能做的事限于这一组：报告是否在线、报告是否已被占用、占用、释放、确保 uiautomator2 已安装、读取屏幕宽高、读取控件树、截图、从截图识别屏幕文字及其区域、按像素点击、长按、滑动、向当前焦点输入文本、按返回或主页、按应用标识和可选入口启动应用、切回输入法。设备接口不提供卸载，也不提供任意命令。
- Android 真机用进程内的 adb 协议连接，控件树、手势、输入、启动应用和截图通过 uiautomator2 完成。不把 adb 可执行文件作为发布路径。屏幕文字用可执行文件旁的 ONNX Runtime 与 PP-OCR 中文模型；缺动态库或模型时，依赖屏幕文字的那一步是错误。
- 测试用的设备实现同一组能力，并记录收到的设备操作。时钟在被要求等待时立刻返回，同时把流逝计入下一次读取。生产环境的时钟是真实时间。
- 一次执行返回前释放设备。没能开始的调用不去占用，也不去释放别人的占用。

## Testing Decisions

- 好的测试只通过执行入口看外部行为。给一条已经载入的用例、一个设备替身和可控时钟，看执行记录，或看这次有没有开始。不测 adb 字节、uiautomator2 报文、ONNX 张量，也不测控件树的内部过滤函数。
- 只设一个接缝，即执行。用例在测试里直接做成载入后的值，不经过文件载入。设备替身按脚本返回控件树、截图、屏幕文字、屏幕尺寸、占用状态和操作成败，并记下收到的操作。
- 断言时限和等待由可控时钟推进。测试不依赖墙钟睡眠，也不依赖 500 毫秒这个间隔的具体数字；只要求时限用尽前会再次读取，时限用尽后才作出不成立的结论。
- 要覆盖的行为：
  - 设备不在线、设备已占用、进程内已有执行，都不开始，也没有执行记录；
  - 安装失败得到错误，且没有任何步骤结论；结束后不出现卸载；
  - 每种动作做完后结论是已执行，发给设备的参数与载入结果一致；
  - 比例 0 和 1 会换算成像素并发出；比例越界不发出手势，结论是错误；
  - 定位器先用控件树；零匹配且只含显示文本时才用屏幕文字；含资源 id、描述或类型时不识别；
  - 动作在零匹配或未写第 n 个的多匹配上是错误；断言对多匹配仍作出成立与否的结论；
  - 前置断言不成立得到阻塞，预期断言不成立得到失败，后面的步骤没有结论；
  - 断言成立则继续；时限内稍后成立则通过；时限用尽才不成立；时限为 0 只读一次；
  - 读取界面失败、截图失败、屏幕文字不可用，得到错误，而不是失败或阻塞；
  - 没有预期断言时结果是已执行；预期断言都成立时结果是通过；
  - 遇到 AI 步骤得到错误并停止；
  - 作出结论的步骤有结束截图，轮询中间画面不在记录里，没开始的步骤不在记录里；
  - 输入法被切换过则在结果确定后切回；切回失败只增加注明，不改变结果；没开始则不切回；
  - 执行前后用例文件字节不变。
- 写法沿用现有的 Go 标准测试和表驱动。这些测试不连接设备、不加载模型、不访问网络。

## Out of Scope

- AI 步骤的模型循环、轨迹、步数上限的消耗。本阶段遇到 AI 步骤即错误。
- 套件。一次入口执行一条用例，不在多条用例之间保持占用，也不处理失败后继续或错误后停住套件。
- 把执行记录写成报告文件、HTML、用浏览器打开、命令行退出码和打印路径。
- 桌面端的表单、设备列表和挑选界面。
- HarmonyOS NEXT 的连接和 uitest。本阶段把设备能做的事定成一组，供它以后实现；本阶段不提供该实现。
- 录制，以及把轨迹导回用例。
- 执行前清理应用、回到主页、自动重试。
- 模型名、模型地址、密钥的读取与传递。
- 发布物如何摆放 ONNX 动态库和 PP-OCR 模型。缺了它们时的执行结果属于本规格，打包方式不属于。

## Further Notes

- 设计里「同一台设备上的第二次执行是错误」。这里把进程内冲突、设备不在线和设备已被占用都做成不开始，因此没有一份结果为错误的执行记录。错误这种结果只留给已经开始、但步骤或安装没有完成的执行。
- 设计里定位器在控件树零匹配时用屏幕文字再找一次。这里把后备限制为「条件只有显示文本，或再加第 n 个」，因为像素回答不了资源 id、描述和类型。
- 断言在多个匹配且没有第 n 个时仍作出结论。动作在同样情况下是错误。设计只把「恰好一个元素」写在动作上。
- 比例 1 落到该边最后一像素（长度减 1），避免合法的边缘比例在执行时变成越界像素。
- HarmonyOS NEXT 以后按同一组设备操作接入。那个实现不会切换输入法，切回调用保持为空操作即可。
