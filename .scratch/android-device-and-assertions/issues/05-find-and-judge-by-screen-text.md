# 05: 用屏幕文字查找并判定

**What to build:** 控件树里一个都没有、而定位器只按显示文本查找时，点击、长按和相关断言再看一次屏幕文字。屏幕上看得见某段文字只看像素。识别不可用是错误，识别跑过但没有这段字才是没看见。

**Blocked by:** 04: 判定断言并给出用例结果

**Status:** ready-for-agent

只有控件树零匹配，且定位器的条件全都是显示文本，或显示文本再加第 n 个，才读取屏幕文字。资源 id、描述或类型出现在定位器里时，仍然只以控件树为准，不读取屏幕文字。控件树已有匹配时，不用屏幕文字改写命中结果。

屏幕文字的区域按先上后下、同一行再先左后右排列。第 n 个按这个顺序从 1 起。点击和长按落在该区域中心。

这次查找必须靠屏幕文字时，截图失败或识别不可用，结论是错误。元素不存在不会因此成立。识别可用但没有对应文字，才是没找到：动作因此是错误，屏幕上看得见因此不成立。

屏幕上看得见不看控件树，只看像素。它遵守上一张工单的时限、轮询、前置和预期规则。轮询中间画面不进入记录。同一段字可以让文本包含成立，同时让屏幕上看得见不成立。

- [ ] 控件树零匹配，且定位器只有显示文本或再加第 n 个时，才读取屏幕文字；区域先上后下、同一行先左后右
- [ ] 点击或长按命中屏幕文字时，点在该区域中心；第 n 个按这个顺序从 1 起
- [ ] 这次查找必须靠屏幕文字时，截图失败或识别不可用是错误；元素不存在不会因此成立
- [ ] 识别跑过但没有这段字时，动作为错误；屏幕上看得见则不成立
- [ ] 屏幕上看得见只看像素；同一段字可以让文本包含成立，同时屏幕上看得见不成立
- [ ] 控件树已有匹配，或定位器含资源 id、描述或类型时，不用屏幕文字改写结果
- [ ] 屏幕上看得见遵守同样的时限、轮询和前置、预期规则；轮询中间画面不进入记录
- [ ] 执行不修改用例文件
