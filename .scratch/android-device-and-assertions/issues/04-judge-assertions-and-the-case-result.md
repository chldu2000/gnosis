# 04: 判定断言并给出用例结果

**What to build:** 同一条用例里的前置断言和预期断言会被判定，用例因此得到通过、失败、阻塞或已执行。元素存在、元素不存在、文本等于、文本包含和属性等于都看控件树。时限之内成立就继续，时限用尽仍不成立才停下。遇到 AI 步骤则是错误。屏幕上看得见留给下一张工单。

**Blocked by:** 03: 按控件树点击和长按

**Status:** ready-for-agent

断言是序列里单独的一步。它是阻塞还是失败，只由它自己标明的前置或预期决定。定位规则与点击相同，但仍允许多个匹配：存在看有没有匹配；不存在看是不是一个都没有；文本等于、文本包含、属性等于看有没有一个匹配满足陈述。第 n 个超出个数视为没找到。显示文本包括屏幕外的节点。属性只比较可用或选中。元素找到了但没有该属性，断言不成立，不是错误。

轮询第一次立即读取。不成立且时限还有剩余时，等待不超过 500 毫秒，也不超过剩余时限，然后再次读取。时限用尽仍不成立，才作出不成立的结论。时限为 0 时只读取一次。时限用载入结果。测试只要求时限用尽前会再次读取、用尽后才作结论，不依赖 500 毫秒这个数字，也不用墙钟睡眠。轮询中间画面不进入记录。结束截图是作出结论那一次读到的画面。轮询中途界面读不出来，该步是错误，不是不成立。

用例结果：

- 断言在时限内成立，该步是通过，继续。
- 前置断言不成立，该步是阻塞，用例结果是阻塞，停止。
- 预期断言不成立，该步是失败，用例结果是失败，停止。
- 步骤都做完后，若至少有一条预期断言且它们都是通过，用例结果是通过；否则是已执行。只有成立的前置断言、没有预期断言时，也是已执行。
- 动作或环境失败，该步是错误，用例结果是错误，停止。前面已经通过的预期断言不改变这个结果。
- 遇到 AI 步骤，该步是错误，用例结果是错误，停止。不调用模型，不写轨迹。

还没执行的步骤没有结论，也没有截图。失败、阻塞和错误都不重试。

- [ ] 找到多个且没写第 n 个时仍作结论：存在即为成立，文本或属性有一个匹配满足即为成立；第 n 个超出则视为没找到
