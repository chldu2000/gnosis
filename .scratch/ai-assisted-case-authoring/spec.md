# 从 AI 执行轨迹编写用例草稿

## Problem Statement

编写者能在报告中看见模型实际做了什么，但把这些动作转成可重复执行的用例仍需手抄。执行期间来源用例还可能被修改。

## Solution

从刚结束且通过的单用例执行生成草稿，逐步复核模型走过的路径，另存为普通用例，再用同一起始状态独立重跑。先交付共享 Go 核心与 CLI，再接入 Windows 工作台。

## User Stories

1. 作为编写者，我想从刚通过的单用例生成草稿，以便复用已走通的步骤。
2. 作为编写者，我想在套件、失败、阻塞、错误、取消或仅已执行时看到无法生成的原因，以免把不完整的执行当作通过。
3. 作为编写者，我想知道是否缺少 AI 步骤或哪一个 AI 步骤没有动作，以便从合适的起始界面重新试跑。
4. 作为编写者，我想草稿基于执行开始时载入的版本，以便磁盘上的后续编辑不会混入草稿。
5. 作为编写者，我想分别展开多个 AI 步骤并保留各轮顺序与参数，以便理解动作在何处发生。
6. 作为编写者，我想已有动作、前置断言和预期断言保留在原位，以便重跑仍检验相同的行为。
7. 作为编写者，我想看到原目标、动作、截图和预期断言，以便识别点击历史记录等绕过待测入口的路径。
8. 作为编写者，我想看出哪些步骤按坐标点击，以便决定保留坐标或修正定位器。
9. 作为编写者，我想显式另存一份可编辑的 YAML，以便保留来源用例并让套件引用新用例。
10. 作为回归负责人，我想在关闭模型配置后独立重跑并验证已知反例，以便判断草稿能否捕捉回归。
11. 作为工作台用户，我想在右栏顶部发起试跑或重跑，在当前会话报告查看结果，以便沿用已有执行习惯。

## Implementation Decisions

- 草稿资格同时取决于执行已结束、单用例结果为通过、至少包含一个 AI 步骤、每个 AI 步骤均留下动作。正常停手和达到上限沿用现有 AI 结果语义。
- 从结构化轨迹和本次载入的用例版本构造草稿。已有步骤继续使用现有格式、校验、编辑和另存行为。坐标待复核属于编写提示。
- 草稿保存到新文件，加入套件由编写者另行操作。每次已开始的试跑或重跑仍只生成一份报告，截图留在会话附件中。
- Windows 桌面通过已有独立执行进程取得对应执行的材料。手动复核和 CLI 优先交付，离线选取定位器由可视化选取元素规格承接。

## Testing Decisions

- 以公开 CLI 为主要入口。沿用现有 CLI 的设备替身和本地模型服务，检查生成的文件、诊断、执行结果、退出码与报告路径。覆盖重复 AI 步骤、执行期间源文件变化以及拒绝生成的组合。
- 用 Android 真机在相同起点对比手写和辅助编写到首次独立通过的耗时，包含人工复核及修订时间。另设动作可完成但预期不成立的状态，确认指定断言报告失败。
- 工作台沿用现有编辑和执行场景，复核、另存并重跑后用 CLI 打开同一份用例。

## Out of Scope

从历史 HTML 报告导入、从需求批量生成测试、自动推断业务预期和视觉语义断言另行评估。
